# AWS Knowledge Graph

A growing, citation-backed knowledge graph of Amazon Web Services: global infrastructure, compute, containers, serverless, storage, databases, networking, identity and security, governance, DevOps and IaC, analytics, AI/ML, migration, cost management, Well-Architected practice, public sector and compliance, and AWS certifications. An hourly scheduled run researches one new topic, writes it as a node with typed edges to the rest of the graph, validates it, and commits it.

## Website

Browse the articles at **https://john1hsu.github.io/aws-graph/**. The site is generated by `scripts/site.py` and redeployed by `.github/workflows/pages.yml` on every push to `main`, so each new article appears there automatically. To preview locally:

```bash
pip install -r requirements.txt
python3 scripts/site.py && python3 -m http.server -d _site 8000
```

## How it's organized

| Layer | What | Where |
|---|---|---|
| Ontology | AWS-specific classes (Service, Feature, Resource, API, Limit, InfrastructureConcept, PricingModel, Pattern, AntiPattern, SecurityControl, ComplianceProgram, Certification, …) and typed relations (dependsOn, runsOn, alternativeTo, governedBy, securedBy, monitoredBy, pricedBy, scopedTo, compliesWith, replacedBy, coveredBy, …) on RDFS/OWL, SKOS and PROV-O | `ontology/ontology.ttl` |
| Nodes | One Markdown article per entity, with YAML frontmatter holding its id, class, hierarchy, typed edges, lifecycle status, the date it was last verified, and per-article provenance | `articles/<domain>/` |
| Graph exports | Linked-data exports regenerated on every commit: JSON-LD, N-Triples, an index | `graph/graph.jsonld`, `graph/triples.nt`, `graph/index.json` |
| Analytics | PageRank centrality, Louvain communities, connected components, coverage by type, domain, verification month and status | `graph/stats.md` |
| Frontier | Nodes existing articles point to but nobody has written yet; the hourly run alternates between expanding this (depth) and the least-covered domain (breadth) | `graph/frontier.md` |

## Guarantees enforced by `scripts/kg.py`

- **Cited:** at least 3 sources per article, at least 2 strong and at least 1 official AWS source (docs or AWS training/exam guide); every source is cited and every substantive paragraph carries a citation.
- **Current:** AWS ships continuously, so each node records the date it was last verified and its lifecycle status. Articles older than 180 days, or verified before the latest re:Invent, are re-verified on odd-hour runs; deprecated or retired services must point to their replacement.
- **Unique:** no duplicate ids, titles or aliases (former service names and abbreviations count); near-paraphrase titles and overlapping text are rejected.
- **Well-formed:** classes and predicates must exist in the ontology.

```bash
pip install -r requirements.txt
python3 scripts/kg.py check                          # validate
python3 scripts/kg.py build                          # validate + regenerate graph/
python3 scripts/kg.py similar "Topic"                # check a candidate for duplicates
python3 scripts/kg.py stale --since 2026-12-04       # what needs re-verifying
```

Steer what gets written by editing `topics/seeds.yaml`. The run playbook is `CLAUDE.md`; the article format is `SCHEMA.md`. The `.nt` and `.jsonld` exports load into RDF tools (Apache Jena, GraphDB, rdflib) or Neo4j via n10s.

Quotas and prices in articles are dated and may vary by Region; confirm them in the current AWS documentation before relying on them.
